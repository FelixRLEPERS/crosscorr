# Как мы работаем над CrossCorr

Это семейный проект. Правила простые: одна задача — одна ветка — один PR —
зелёный CI — ревью — merge.

## Порядок работы (для детей — через GitHub Desktop)

1. Найти задачу в `docs/academy/README.md` или в Issues.
2. Создать ветку `feature/<кто>-<что>`, например `feature/egor-wspr-rows`.
3. Сделать изменение.
4. Проверить себя:
   ```
   python -m pytest tests/ -m "not slow" -q
   python -m ruff check crosscorr_lib/ tests/ scripts/ data/
   ```
5. Закоммитить понятным сообщением:
   `add: 10 rows to wspr sample (Егор)`
6. Открыть Pull Request.

## Ревью

Цепочка: **автор → проверяющий (другой ребёнок) → Алексей → merge**.

Чек-лист PR (заполняет автор):
- [ ] Что сделал (1–2 предложения)
- [ ] Как проверить (команда)
- [ ] Какой тест добавлен / обновлён
- [ ] Скриншот или вывод, если применимо

Алексей проверяет: корректность, безопасность, не сломаны ли тесты.
CI должен быть зелёным до merge в `main`.

## Что нельзя без взрослого

- `crosscorr_lib/analysis/surrogate.py`, `mantel.py`, `pairs.py`,
  `cross_correlation.py` — там математика, которую легко сломать.
- `.github/workflows/**`, `pyproject.toml` — инфраструктура.
- Не коммитить секреты: `.env`, `opencode.json`, ключи.

## Журнал

После merge — короткая запись в `docs/journal/YYYY-MM-DD.md`:
что сделал и чему научился.
