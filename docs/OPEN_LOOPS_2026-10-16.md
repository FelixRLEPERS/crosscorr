## Finding 1: подписи баров fig3 в paper/ — bootstrap mean, а не point estimate

- **Дата:** 2026-10-16
- **Обнаружено:** при подготовке презентации HamSCI (сверка подписей
  на `paper/figures/fig3_frequency_dependence.png` с текстом статьи).
- **Суть:** `scripts/make_paper_figures.py`, строка 546
  (`freq_drops[band] = float(-drop_dist.mean())`) использует среднее
  по 1000 бутстрап-пересэмплам (bootstrap mean) как высоту бара и
  подпись fig3. Текст статьи, Table 3 (`tab:main`) и
  `results/perm_test_18mo_3band.json` используют point estimate
  `100*(mean_storm - mean_quiet)/mean_quiet` на сырых значениях.
- **Величина расхождения:** ~0.1 п.п. (фигура показывает 27.6 / 27.3 /
  38.6; point estimate = 27.7 / 27.2 / 38.7).
- **Дополнительно:** bootstrap mean недетерминирован — его знаки после
  запятой зависят от позиции в общем RNG-потоке скрипта (fig3 считается
  после fig1/fig2, которые потребляют часть потока). При любых
  изменениях upstream-фигур подписи fig3 могут "плавать".
- **Тот же баг-класс уже исправлен для fig4** в session 14
  (коммит `867af34`: подписи переключены на point estimate с локальным
  seed-42; RNG burn сохранил fig1/2/3/5 byte-identical). Для fig3
  правка не делалась.
- **Мелочь:** в блоке fig3 считается колонка `resid` (строки 533–535)
  и не используется — бутстрап идёт по сырым `value`. Мёртвый код.
- **Кандидат:** v1.3.2 (перед submission в Space Weather).
- **Действие перед submission:**
  1. В `scripts/make_paper_figures.py` подписи fig3 переключить на
     point estimate (строка 546). RNG-поток НЕ менять, чтобы fig1,
     fig2, fig4, fig5 остались byte-identical.
  2. Перегенерировать fig3, сверить md5 остальных четырёх фигур.
  3. Пересобрать `paper/main.pdf`, сверить, что подписи на фигуре
     совпадают с текстом (27.7 / 27.2 / 38.7).
- **Смягчение для презентации (сделано 2026-10-16):** создана
  презентационная копия
  `docs/presentations/hamsci_2026-11-05/figures/fig3_frequency_dependence_pointest.png`
  (подписи = point estimate, CI = 95% bootstrap с локальным seed 42;
  md5 `201c1ef7023bd3fcb78d87a8f15240df`; генератор
  `tmp_fix_pres_3_fig3.py`). Слайд 4 презентации использует её.
  `paper/figures/fig3_frequency_dependence.png` (md5
  `83b81c615a4d5b21deb365677247b885`) не тронут.

## Finding 2: NUMBERS_MAP_2026-10-15.md устарел в части A7 (N=23)

- **Дата:** 2026-10-16
- **Обнаружено:** при сверке слайдов 5 и 7 презентации со статьёй.
- **Суть:** пункт A7 карты (`N=23 storm hours`, строки 890/902

  текущем v1.3.1 фразы "N = 23" нет вообще (grep: 0 совпадений);
  held-out — это `N_storm = 47` epochs (Table 8, `tab:heldout`,
  числа live-перекачки 2026-10-15). Карта создавалась в session 10,
  до переработки held-out в session 14 (коммит `73ac6a4`).
- **Сопутствующая путаница (зафиксировать):** нумерация таблиц
  сместилась на +1 при вставке Table 2 (`tab:provenance`, session 15,
  batch 19). Поэтому старые записи вида "Table 7 = held-out"
  (AUDIT_START, session 10b) относятся к старой нумерации; в v1.3.1
  held-out — это **Table 8**, а Table 7 — day/night (training).
- **Действие:** при следующем использовании NUMBERS_MAP учитывать
  устаревание A7. Либо обновить карту при следующей ревизии
  main.tex — `audit/` менять только с явного разрешения пользователя.
