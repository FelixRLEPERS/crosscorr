# Данные CrossCorr — как это работает

## Что здесь лежит

```
data/
├── raw/              ← сырые данные. НЕ редактируй руками.
│   │                   Создаётся автоматически при загрузке.
│   ├── wspr/         ← радиосигналы с WSPR
│   ├── horizons/     ← положения планет (JPL Horizons)
│   ├── intermagnet/  ← магнитное поле Земли (появляется, когда скачаешь вручную)
│   └── space_weather/← Kp, Dst, F10.7 — индексы космической погоды
├── processed/        ← финал: unified.parquet. Создаётся автоматически.
│   │                   Основной анализ читает только отсюда.
└── scripts/          ← программы, которые всё это собирают
```

Каждый файл в `raw/` — одна загрузка за определённые даты.
Не удаляй их: `unify_schema.py` склеивает их в один файл
`processed/unified.parquet`, с которым работает весь анализ.

## Как собрать данные (пошагово)

1. Открой `data/scripts/config.yaml` в блокноте.
2. Поменяй даты `start` и `end` на нужные.
   **⚠ Используй ПРОШЛЫЕ даты.** WSPR-сервер зависает на будущих датах.
   Даты в config.yaml — это значения по умолчанию. Если при запуске
   указать `--start` и `--end`, они переопределят config.yaml.
3. Открой PowerShell в папке `G:\crosscorr`.
4. Запусти загрузку всех источников:
   ```
   python data/scripts/fetch_all.py --start 2026-08-01 --end 2026-08-15
   ```
   Или только те, что нужны:
   ```
   python data/scripts/fetch_all.py --start 2026-08-01 --end 2026-08-15 --only wspr,kp,dst
   ```
5. Дождись окончания. WSPR качается ~5 секунд на день,
   остальные источники — почти мгновенно.
6. Проверь, что всё собралось:
   ```
   python -c "import pandas as pd; print(pd.read_parquet('data/processed/unified.parquet').shape)"
   ```
   Ты увидишь что-то вроде `(850, 9)` — число строк и колонок.

## Что делать, если не работает

| Что случилось | Что делать |
|---|---|
| «файл не найден» или «No module named» | Проверь, что PowerShell открыт в `G:\crosscorr` |
| WSPR: 0 строк или «сервер недоступен» | 1. Проверь дату — она должна быть прошлой. 2. Сервер иногда не отвечает (даже на прошлые даты). Тогда запусти `fetch_all.py --only kp,dst,horizons`, а WSPR попробуй позже. |
| Horizons sun: ошибка | Используй moon/mars/… sun пока не работает (ограничение astroquery). |
| INTERMAGNET: нет данных | Скачаются вручную с intermagnet.org. В конце работы `fetch_all.py` печатается инструкция. |
| F10.7: 1 строка — это нормально | Данные только месячные. Для коротких диапазонов так и должно быть. |
| Совсем не работает | Покажи **полный текст ошибки** взрослому (папа / учитель). |

## Какие источники сейчас подключены

| Источник | Что даёт | Сам? |
|---|---|---|
| WSPR | Радиосигналы (SNR) со всего мира | Да (только прошлые даты) |
| JPL Horizons | Расстояния от Солнца до планет (moon, mars, ...) | Да (кроме sun) |
| Kp | Индекс геомагнитной активности (0–9, каждые 3 часа) | Да |
| Dst | Индекс геомагнитных возмущений (нТ, каждый час) | Да |
| F10.7 | Солнечный радиопоток (sfu, раз в месяц) | Да |
| INTERMAGNET | Магнитное поле Земли (X, Y, Z) с обсерваторий | Нет, вручную |

## Что такое детекторы, value и timestamp

**Детектор** (detector_id) — любой источник измерений. У каждого есть
уникальное имя. Например:

- `DF4UE` — радиоприёмник WSPR со своим позывным
- `horizons_moon_2026-08-01_2026-08-02` — эфемериды Луны
- `MOS` — магнитометр на станции Москва (INTERMAGNET)
- `kp_index` — индекс Kp
- `dst_index` — индекс Dst
- `f107_index` — индекс F10.7

**value** — сырое измерение. Что измерено — зависит от детектора:
- WSPR → SNR (отношение сигнал/шум, в dB)
- Планеты → расстояние от Солнца (в астрономических единицах)
- Магнитометры → компонента X магнитного поля (в нТ)
- Kp → индекс 0–9
- Dst → возмущение (в нТ)
- F10.7 → радиопоток (в sfu)

**timestamp_utc** — время измерения по Гринвичу (UTC).
Все данные в проекте хранятся в UTC, чтобы не путаться с часовыми поясами.

**residual** — это `value` минус всё, что можно объяснить
конфаундерами (Kp, Dst, F10.7). Эти остатки мы и сравниваем
между детекторами в основном анализе.

## Добавить новый источник

Хочешь подключить что-то новое? Вот что нужно сделать:

1. Напиши `data/scripts/download_<имя>.py` — скрипт, который качает сырые данные.
2. Добавь loader в `data/scripts/unify_schema.py` — код, который читает CSV и превращает его в unified-формат.
3. Пропиши источник в `data/scripts/config.yaml`.
4. Добавь вызов в `data/scripts/fetch_all.py`.
5. Обнови эту инструкцию.

Подробнее — в `docs/DATA_PIPELINE.md`.
